あなた / ブラウザ / 初回

あなた / Windows の OpenSSL ＋ Apple のブラウザ画面 / 初回・証明書更新時

OpenSSL を利用できる状態にし、リポジトリ外の非同期フォルダ（例：C:\Users\あなた\ios-signing）で PowerShell を開きます。以下のファイル名は例です。

openssl version
openssl req -new -newkey rsa:2048 -keyout distribution.key -out distribution.csr
  1. 秘密鍵のパスフレーズを設定し、質問に沿って情報を入力する。パスフレーズは安全に保管する。
  2. Apple Developer → Certificates → ＋ → Apple Distribution を選び、distribution.csr をアップロードする。
  3. 証明書をダウンロードし、同じフォルダに distribution.cer として保存する。
openssl x509 -inform DER -in distribution.cer -out distribution.pem
openssl pkcs12 -export -inkey distribution.key -in distribution.pem -out distribution.p12 -name "Apple Distribution"

秘密鍵のパスフレーズを入力し、続いて Export Password を設定します。この Export Password が GitHub Secret の IOS_DISTRIBUTION_CERTIFICATE_PASSWORD です。証明書単体の .cer では署名できず、秘密鍵を含む .p12 が必要です。

完了の目安：distribution.p12 と Export Password を用意できた。CSR / p12

あなた / ブラウザ / 初回・更新時
  1. Apple Developer → Profiles → ＋ → Distribution の App Store Connect 用プロファイルを選ぶ。
  2. 手順2の App ID と、手順4の Apple Distribution 証明書を選ぶ。
  3. 作成し、.mobileprovision をダウンロードする。以下では profile.mobileprovision として扱う。

Development・Ad Hoc・Enterprise 用は現在のワークフローでは使えません。期限が有効で、Push Notifications と Sign in with Apple を含む必要があります。公式手順

あなた / ブラウザ / 初回
  1. App Store Connect → Users and Access → Integrations → App Store Connect API へ進む。アクセス申請が表示される場合は Account Holder で手続きする。
  2. 現在のワークフロー用に チーム API キーを作成する。アップロードできる権限（例：App Manager）を選ぶ。
  3. Key ID、Issuer ID、秘密鍵 AuthKey_….p8 を保管する。秘密鍵のダウンロードは一度だけなので保存する。

これは App Store Connect へのアップロード用キーです。次の手順の APNs キーとは別物です。公式手順

あなた / Firebase・Apple のブラウザ画面 / 初回・設定確認
  1. Firebase Console → 対象プロジェクト → プロジェクトの設定 → iOS アプリを確認する。なければ Bundle ID com.kansuke.kansuke で登録する。
  2. GoogleService-Info.plist をダウンロードする。現在の準備スクリプトは CLIENT_ID と REVERSED_CLIENT_ID を使用するため、Google ログイン設定を確認し、これらを含む設定ファイルを用意する。
  3. Firebase Authentication で Google と Apple のログインが有効で、必要なプロバイダー設定が済んでいるか確認する。
  4. 通知用に Apple Developer で APNs 認証キーを用意し、Firebase → プロジェクトの設定 → Cloud Messaging → 対象 iOS アプリに、APNs キー・Key ID・Team ID を登録する。TestFlight は production APNs を使用する。

APNs キーは Firebase に登録します。今回の GitHub Actions に渡す App Store Connect API キーとは用途が違います。通知の公式手順

あなた / PowerShell ＋ GitHub のブラウザ画面 / 初回・更新時

手順4・5のフォルダで、次のように Base64 をクリップボードにコピーします。1つ目を GitHub に登録してから2つ目を実行してください。

[Convert]::ToBase64String([IO.File]::ReadAllBytes((Resolve-Path .\distribution.p12).Path)) | Set-Clipboard
# 1つ目を登録した後に実行
[Convert]::ToBase64String([IO.File]::ReadAllBytes((Resolve-Path .\profile.mobileprovision).Path)) | Set-Clipboard

GitHub のリポジトリ → Settings → Secrets and variables → Actions → New repository secret に登録します。

Secret 名登録する値
IOS_DISTRIBUTION_CERTIFICATE_BASE64distribution.p12 の Base64

秘密鍵・p12・設定ファイルをリポジトリにコミットしたり、このチェックリストに書き込んだりしないでください。

あなた → GitHub Actions / 初回・毎リリース
  1. e12f7b5 の TestFlight ワークフローが main に入っていることを確認する。
  2. pubspec.yaml の version: バージョン+ビルド番号 を確認する。再アップロード時はビルド番号を更新し、main に反映する。同じ番号のまま再実行しても番号は自動更新されない。
  3. main への push に pubspec.yaml の変更が含まれると自動実行。それ以外は GitHub → Actions → Upload IPA to TestFlight → Run workflow → main を選んで実行する。
  4. Actions の成功を確認する。依存取得 → フォーマット検査 → テスト → IPA ビルド → アップロードまでが自動。

完了の目安：ワークフロー成功後、App Store Connect → KanSuke → TestFlight にビルドが表示され、Apple の処理が完了した。

あなた / App Store Connect ＋ 家族の iPhone / 初回・配布時
  1. TestFlight で表示された輸出コンプライアンス等の質問に、実際のアプリに沿って回答する。
  2. 家族向けの 外部テスターグループを作り、ビルドを追加する。
  3. テスト内容・連絡先などを記入して、必要な TestFlight App Review に提出する。審査側からログイン方法を求められた場合は、実際に検証できる方法を用意する。
  4. 承認後、家族のメールアドレスで招待する。閉じた運用のため公開招待リンクは使わず、対象者を指定する。
  5. 家族は iPhone に無料の TestFlight アプリを入れ、招待を承諾して KanSuke をインストールする。

GitHub Actions はアップロードまでです。テスター設定と審査・配布操作は App Store Connect 側で行います。外部テスターの公式手順

あなた・家族 / iPhone / 初回・継続運用
  • Google / Apple ログイン、家族カレンダー参加、予定の作成・編集・同期を確認する。
  • 通知許可、リマインド受信、オフライン表示と再接続後の同期を確認する。
  • TestFlight の期限が切れる前に、ビルド番号を上げた新しいビルドを配布する。目安としてアップロードから60日後に更新確認の予定を入れる。
  • Apple Developer Program の年次更新、証明書・プロファイルの期限を管理する。更新したファイルは GitHub Secrets にも反映する。

Windows では Xcode や iOS シミュレーターを使えないため、iOS の問題は Actions のログと iPhone 実機で確認します。実際の署名・アップロードの成功は初回実行で確認してください。

止まったときの確認先

  • 自動で動かない：main に入り、pubspec.yaml の変更が push に含まれているか。含まれなければ手動実行。
  • Secret required：手順8の名前と値を確認。p12 のパスワードも必要。
  • プロファイル検証エラー：Bundle ID、App Store 用、期限、Push Notifications、Sign in with Apple を確認。
  • 証明書読み込みエラー：p12 が秘密鍵を含むか、Export Password と Base64 が一致するか。
  • Firebase 設定エラー：Bundle ID と CLIENT_ID / REVERSED_CLIENT_ID を確認。
  • ビルド番号の重複：pubspec.yaml の + 以降の番号を増やして main に反映。
  • アップロード成功後も家族が使えない：Apple の処理、審査、グループへのビルド追加、招待、有効期限を確認。
